# browserfly

Top-down fruit flies that wander over a web page. They walk in runs and pauses, turn, and can be
drawn toward the cursor or pushed away from it. The fly is a sprite rendered from
[NeuroMechFly](https://neuromechfly.org/), a biomechanical model of *Drosophila melanogaster*,
replaying a recorded real walking stride, so the legs move in a true tripod gait without sliding.

One script tag, no dependencies, about 8 KB gzipped (plus a 28 KB sprite sheet, or one 37 KB file
with the sheet inlined). The overlay never blocks clicks, never scrolls or shifts the layout, and
respects `prefers-reduced-motion`.

## Quick start

Copy two files from [`dist/`](dist/) next to your page, `fly.min.js` and `fly-sheet.webp` (add
`fly-sheet.png` as a fallback for old browsers), then add one tag:

```html
<script src="fly.min.js" data-fly data-count="2" data-attraction="0.4" defer></script>
```

The sprite sheet is found relative to the script's own URL, so this works on GitHub Pages project
sites served under `/<repo>/` too.

### Single file

`fly.inline.min.js` has the sprite sheet embedded, so no image file is needed:

```html
<script src="fly.inline.min.js" data-fly defer></script>
```

### Programmatic

```html
<script src="fly.min.js" defer></script>
<script defer>
  const swarm = Fly.create({ count: 3, attraction: -0.5 });
  // swarm.set({ attraction: 0.8 });  swarm.pause();  swarm.resume();  swarm.destroy();
</script>
```

### Inside an element

Instead of the whole viewport, the flies can live inside one element. The canvas is added to the
element (which is made `position: relative` if it is static):

```js
Fly.create({ container: document.querySelector('#hero'), count: 1 });
```

### Flies that scroll with the page

By default (`anchor: 'page'`) the flies live on the page: they keep their place on the content and
scroll away with it, and the ones you've scrolled past keep walking out of sight. New flies appear in
the part of the page that's visible, then roam the whole page. With `anchor: 'viewport'` they stay on
screen instead, while the page scrolls under them:

```html
<script src="fly.inline.min.js" data-fly data-anchor="viewport" defer></script>
```

Only ordinary vertical scrolling of the document is supported (not horizontal scrolling or
scrolling inside other elements). The canvas stays the size of the window, so long pages cost
nothing extra. With a `container`, `anchor` is ignored: a container already scrolls with its content.

`fly.esm.js` is an ES module build exporting `create`, `version`, `instances` and `schema`. A
module has no `currentScript`, so pass `sprite` as a URL (e.g.
`new URL('fly-sheet.webp', import.meta.url).href`), or the flies are drawn procedurally.

## Options

Options can be passed to `Fly.create({...})`, changed live with `swarm.set({...})`, or given as
data attributes on the auto-init script tag (kebab-case: `data-run-mean="3"`). Out-of-range values
are clamped and unknown options are ignored, each with one console warning. BL is the fly's body
length (`size`).

The default walking speed is slow motion on purpose: a real fly walks about 6 body lengths per
second with its legs stepping at about 11 Hz, which is too fast to see individual legs on a 60 Hz
screen.

## API

```ts
Fly.create(options?) → Swarm
Fly.version: string
Fly.instances: Swarm[]          // the auto-init swarm is Fly.instances[0]
Fly.schema                      // the option schema (defaults, ranges)

swarm.set(partialOptions)       // live update; count changes add or remove flies; a new seed restarts
swarm.pause() / swarm.resume()
swarm.destroy()                 // removes the canvas, listeners and observers; safe to call twice
swarm.debug() → { flies, cursor, bounds, anchor, scroll, fps, renderer, sheetUrl, params, running }   // read-only snapshot
```

## How it behaves

Each fly alternates runs, stops and reorientations. During a run its heading drifts smoothly and
is steered toward an attractive cursor (or away from a repulsive one); runs heading toward an
attractive cursor last longer, and new headings are biased toward it. Attracted flies stop at the
cursor, linger for up to `lingerMax` seconds, then wander off. Soft walls keep them on screen. The
behaviour engine is pure and deterministic given `seed`, and is verified by statistical unit tests
([PLAN.md §4](PLAN.md)).

The animation frame follows the distance walked (one sprite stride per `strideBL` body lengths), so
the feet don't slide at any speed. The animation runs on one `requestAnimationFrame` loop, only
while the page is visible (and, in container mode, while the container is on screen).

## Accessibility

- The canvas is decorative: `aria-hidden="true"` and `role="presentation"`, `pointer-events: none`,
  never focusable, and it never captures or prevents pointer events.
- `prefers-reduced-motion: reduce` is respected, and live changes to it are followed.
  `reducedMotion: 'static'` (default) shows the flies standing still, `'hide'` shows nothing, and
  `'ignore'` animates anyway.
- On touch screens, a tap acts as the cursor for `touchTargetTimeout` seconds.

## Browser support

Current Chrome, Edge, Firefox and Safari. The code targets ES2020 (Chrome 80+, Firefox 74+,
Safari 13.1+). WebP needs Safari 14+; older browsers use `fly-sheet.png`, and if no sheet can be
loaded the flies are drawn procedurally (with one console warning). Tested with Playwright on
Chromium, Firefox and WebKit, including touch emulation, 2× pixel density and reduced motion.

## Development

```bash
npm install
npx playwright install        # browsers for the e2e tests
npm run build                 # dist/ bundles; prints gzip sizes against the budgets
npm test                      # unit tests (vitest), including the statistical engine tests
npm run test:sweep            # statistical tests under 20 different base seeds
npm run test:e2e              # end-to-end tests in Chromium, Firefox and WebKit
npm run lint
npm run docs                  # regenerate the option table above from src/params.js
npm run serve                 # http://localhost:8080/demo/ — demo with a live parameter panel
```

The demo page (`demo/index.html`) has sliders for every option, renderer and anchor toggles, a seed
box, a debug overlay and a box listing the options you've changed from the defaults. The debug
overlay's per-fly text labels are only drawn by the debug build (`fly.js`); the minified builds draw
the overlay without them. In the demo the quotation's text wraps around the flies
(`demo/textwrap.js`, demo-only, not part of the library): it re-wraps as each fly moves, settled so
a paragraph is only re-laid out after a fly has moved a few pixels. `?wrap=off` (or the panel)
leaves layout to the browser.
[PLAN.md](PLAN.md) is the full specification and [PROGRESS.md](PROGRESS.md) the project log.

## Regenerating the sprite sheet

The sheet is built offline by a Python pipeline in [`pipeline/`](pipeline/) (see its
[README](pipeline/README.md) for details and FlyGym API notes). It needs Python 3.12 and about
1 GB of disk for the virtual environment. CI does not run it; its outputs in `dist/` are committed.

```bash
uv venv -p python3.12 pipeline/.venv
uv pip install -p pipeline/.venv/bin/python -r pipeline/requirements.txt
pipeline/.venv/bin/python pipeline/build_all.py pipeline/out/build --dist   # ~30 s
pipeline/.venv/bin/python pipeline/contact_sheet.py final dist/fly-sheet.json pipeline/out/qa
pipeline/.venv/bin/python -m pytest pipeline/tests
npm run build                 # re-embed the new sheet in the bundles
```

The pipeline replays a recorded walking stride in NeuroMechFly (FlyGym 2.1.0, MuJoCo 3.9.0),
renders it from directly overhead with an orthographic camera, picks one seamlessly looping stride,
aligns the frames head-up around the thorax, and packs a 16-frame walk and a 2-frame idle clip
into a 64-colour sheet. The wings are a translucent grey-blue so they show on white pages
(`--wing-rgba` changes it). The build is deterministic.
